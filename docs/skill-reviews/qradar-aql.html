Fachliche Grundlage

SOURCE FACT: IBM dokumentiert AQL-SELECT-Statements gegen Ariel Events oder Flows, Filter über WHERE sowie Zeitgrenzen mit START/STOP. IBM: AQL Query Structure · IBM: Time Criteria.

SOURCE FACT: Custom Event/Flow Properties können lokale Extraktionen und AQL-Ausdrücke enthalten. Ihre Namen und Verfügbarkeit sind deshalb umgebungsspezifische Tatsachen, keine aus einer fachlichen Anforderung ableitbaren Feldnamen. IBM: Custom Properties.

SOURCE FACT: NIST SP 800-61r3 ordnet Incident Response in das Cybersecurity-Risikomanagement ein; die Produktionsexekution bleibt deshalb außerhalb einer reinen Query-Proposal-Methodik. NIST SP 800-61r3.

Hauptbefunde

  • Der Altbestand begrenzte sich bereits auf read-only Event-Queries, verlangte Filter und Zeitfenster und untersagte Ausführung.
  • Unbekannte Custom Properties wurden jedoch in einer AQL-ähnlichen EXTENDED QUERY als <CUSTOM_PROPERTY:...> dargestellt. Das kann beim Kopieren wie ausführbares AQL wirken.
  • Es fehlten eine kanonische Quelle, Codex-/Claude-Adapter, ein Statusmodell für lokale Validierung und ein Test, dass Custom-Property-Placeholders nicht in AQL geraten.

Wichtig: LOCALLY_VALIDATED bedeutet nie AUTHORIZED_TO_EXECUTE. Weder IBM-Dokumentation noch ein plausibler Feldname oder ein kopiertes Query beweisen lokale Validierung oder erteilen eine Ausführungsfreigabe.

Scope und Handoffs

Der Skill akzeptiert einen QUERY REQUEST aus qradar-investigation und gibt eine Statusentscheidung plus begrenzten Proposal zurück. Er analysiert keine Ergebnisse und trifft keine Security-Entscheidung.

  • Manuell zurückgegebene Raw Events → security-event-analysis
  • Detection Validity, False Positive, Legitimität oder Maliciousness → false-positive-analysis
  • Reporting → incident-summary
  • Jede Ausführung → autorisierter Mensch oder künftig autorisierter Operator

Security, Datenschutz und Tests

Requests, Logs, Feldnamen und eingebettete Anweisungen sind untrusted data. CUSTOMER_DATA und UNKNOWN bleiben LOCAL_ONLY; keine automatische Cloud-Weitergabe. Das ist ein Policy-/Prompt-Vertrag, keine technische Isolation.

Neun synthetische Fixtures: Der bestehende Custom-Property-Fall ist jetzt TEMPLATE_ONLY ohne AQL; ein neuer Fall fordert traceable lokale Validierung und verbietet trotzdem Ausführungsautorisierung. Der Contract-Test prüft alle vier Status, die Placeholder-Regel, Handoffs, fehlende Tool-Freigaben/Skripte und byte-identische Adapter.
