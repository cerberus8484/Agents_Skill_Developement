Skill Review: Design System

Evidenz: PARTIALLY_VERIFIED · Framework-Reife: YELLOW

Inventar und Entscheidung

Es existierte kein Skill mit der ID design-system. Der externe ECC-Skill frontend-design ist ein Visual-Design-/Frontend-Leitfaden, kein Design-System-Skill, und blieb unverändert. Deshalb ist framework/skills/design-system eine neue kanonische Quelle mit Adaptern für GitHub Copilot, Codex und Claude Code.

Scope und Grenzen

Der Skill prüft Komponenten, Tokens, Varianten, States, Naming, Komposition und Dokumentation sowie begrenzte Accessibility-Aspekte. Er beweist keine UX-Qualität, genehmigt kein Branding, ersetzt keine Nutzerforschung und zertifiziert keine WCAG-Konformität.

Quellenklassifikation

STANDARD: WCAG 2.2 definiert testbare Erfolgskriterien und Seiten-Konformität. Die WAI-ARIA APG liefert empfohlene Semantik- und Tastaturmuster, ist aber kein UI-Design-System.

COMMUNITY SPECIFICATION: Die Design Tokens Format Module 2025.10 ist ein stabiler Final Community Group Report der Design Tokens Community Group. Sie dient als technische Interoperabilitätsreferenz für Token-Struktur, Typen, Gruppen und Aliase. Die Resolver- und Color-Module haben denselben Status; Resolver beschreibt Kontexte wie Light, Dark und High Contrast. Keine dieser Spezifikationen ist eine W3C Recommendation oder eine W3C-Standards-Track-Spezifikation.

ESTABLISHED PRACTICE: Tokens, Komponenten und Governance fördern Konsistenz, ohne ein UX-Ergebnis zu garantieren. FRAMEWORK RECOMMENDATION: Lokale Namens- und Strukturentscheidungen werden als solche gekennzeichnet.

Tests und Plattformen

Contract Tests prüfen die Quellenklassifikation, die Grenzen, Ressourcen und identische Adapter. Runtime: GitHub Copilot RUNTIME_NOT_AVAILABLE, Codex RUNTIME_BLOCKED_ENVIRONMENT, Claude Code RUNTIME_BLOCKED_AUTH. Adapter sind kein Runtime-Nachweis.
