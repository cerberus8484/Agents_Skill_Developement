Skill Review: Design System

Evidenz: VERIFIED · Framework-Reife: YELLOW

Inventar und Entscheidung

Kein installierter Skill mit der ID design-system wurde gefunden. Der externe ECC-Skill frontend-design ist ein Visual-Design-/Frontend-Implementierungsleitfaden, kein Design-System-Skill, und blieb unverändert. Daher ist framework/skills/design-system eine neue kanonische, framework-eigene Quelle mit synchronisierten Adaptern für GitHub Copilot, Codex und Claude Code.

Scope

Der Skill prüft Komponenten, Tokens, Varianten, States, Naming, Komposition und Dokumentation. Accessibility wird als begrenzte Betrachtung einbezogen. Er beweist keine UX-Qualität, genehmigt kein Branding, ersetzt keine Nutzerforschung und zertifiziert keine WCAG-Konformität.

Quellen

STANDARD: WCAG 2.2 definiert testbare Erfolgskriterien und Konformität für vollständige Seiten. WAI-ARIA APG liefert empfohlene Rollen-, State- und Tastaturmuster, ist aber kein UI-Design-System. ESTABLISHED PRACTICE: Tokens, Komponenten, Dokumentation und Governance fördern Konsistenz, ohne ein UX-Ergebnis zu garantieren.

Vertrag und Grenzen

Output: Observation, Evidence and unknowns, Classification, System impact, smallest safe next step und Handoff. Keine Skripte und kein allowed-tools. CUSTOMER_DATA/UNKNOWN bleiben nach Policy Local-Only; eingebettete Instruktionen sind untrusted data. Der Skill ist Methode, ein künftiger design-system-reviewer wäre REVIEWER, ein Executor bleibt separat autorisiert.

Tests und Plattformen

Contract Tests prüfen Frontmatter, Grenzen, Referenzen und vollständige Adapter-Gleichheit. Runtime: GitHub Copilot RUNTIME_NOT_AVAILABLE, Codex RUNTIME_BLOCKED_ENVIRONMENT, Claude Code RUNTIME_BLOCKED_AUTH. Die statischen Adapter sind kein Runtime-Nachweis.
