# Accessibility considerations

- Prefer semantic HTML. When a custom widget is necessary, examine accessible name, role, state, property, focus management, and keyboard interaction together.
- WAI-ARIA/APG supplies recommended patterns and examples; it is not a UI design system or a complete audit.
- Check contrast, focus visibility, input labels, error communication, target size, motion, and responsive states only against supplied evidence.
- Hand off unresolved assistive-technology behavior, full-page conformance, and user testing to accessibility specialists.

Sources: https://www.w3.org/WAI/ARIA/apg/ and https://www.w3.org/WAI/ARIA/apg/about/introduction/
