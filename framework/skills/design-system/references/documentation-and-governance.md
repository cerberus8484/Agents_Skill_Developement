# Documentation and governance

- Look for intent, token naming, component anatomy, variants, states, accessibility notes, examples, ownership, versioning, and migration guidance.
- Identify duplicate or divergent components, but do not mandate a merge without evaluating product and domain differences.
- Route brand decisions to brand owners, user-outcome questions to UX research, and implementation changes to authorized executors.

**FRAMEWORK RECOMMENDATION:** A design system is a maintained product capability, not merely a repository of components.
